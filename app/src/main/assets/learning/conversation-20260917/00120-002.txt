동일 진영 버프를 반드시 평가 요소에 포함하라. 다만 진영 버프의 정확한 임계치와 수치가 정본 자료에 없다면 값을 만들어내지 말고 `진영 시너지 고려` 정도로만 표시한다. 탱커나 힐러가 없는 조합을 진영 숫자만 보고 추천하지 마라.

출전 영웅 10명을 추천할 때 다음을 준수한다.

- 사용자가 실제 보유한 영웅만 사용한다.
- 같은 진영 버프를 고려한다.
- 전열, 지속 회복, 제어, 단일 대상 딜, 광역 딜, 심층 생존을 함께 평가한다.
- 영웅마다 검증된 초상화를 표시한다.
- 초상화가 없으면 다른 영웅 이미지를 대신 사용하지 않는다.
- 이미지가 없는 영웅은 명칭과 `이미지 미검증` 상태를 표시한다.

선택지가 하나뿐이면 추천 등급 경쟁을 만들지 마라. 다음과 같이 표현한다.

`진행 가능한 경로가 하나뿐입니다: 아이템 게이트`

다음과 같은 표현은 금지한다.

`아이템 게이트 선택을 추천합니다`

# 배치 인식 요구사항

- 캐릭터 sprite 중심이 아니라 발밑 anchor를 사용한다.
- 발밑 anchor를 가장 가까운 hex polygon에 연결해 tileId를 결정한다.
- 사람이 예상한 좌표보다 실제 점유 tile을 우선한다.
- 영웅이 만든 소환물이나 동적 효과를 고정 맵 타일로 저장하지 않는다.
- 전투에 추가로 배치해야 할 영웅 수를 파악하지 못했으면 `현재 배치 유지`를 추천하지 않는다.
- 가능하면 원본 캡처 위에 추천 위치와 영웅 초상화를 표시한 주석 이미지를 만든다.
- 45초 내 주석 이미지를 만들 수 없으면 텍스트 배치를 먼저 표시한다.
- 주석 이미지 실패가 추천 전체 실패로 이어지지 않게 한다.

# 자산 저장 원칙

- 이름 검증용 원본 이미지는 test fixture 또는 연구 자료로 둔다.
- APK production assets에는 필요한 portrait crop과 최소 manifest만 넣는다.
- 14MB 전체 ZIP과 전체 원본 캡처를 무조건 APK에 포함하지 마라.
- 사용자 계정명, 전투력 등 개인정보성 화면이 production APK에 포함되지 않게 한다.
- 파일명보다 안정적인 내부 heroId를 사용하고 한국어 이름은 display label로 둔다.
- 잘못된 초상화를 보여주는 것보다 빈 이미지와 `미검증` 상태가 낫다.
- 모델 fine-tuning이 완료됐다고 표현하지 마라.
- 이 자료는 template/reference 기반 Ground Truth다.

# 최소 회귀 테스트

현재 테스트 구조를 재사용해 다음을 검증한다.

- `휴윈`이 `후긴`으로 변환되지 않는다.
- `휴긴`만 `후긴`으로 정규화된다.
- `류윈`은 자동 매칭되지 않는다.
- 세시아 초상화가 세시아에 연결된다.
- 에이론 초상화가 에이론에 연결된다.
- 에이론 초상화가 다른 영웅에게 중복 연결되지 않는다.
- 선택지가 하나일 때 경쟁 추천 문구가 생성되지 않는다.
- 난이도 5 탐색 등록 10명과 실제 배치 5명이 분리된다.
- Elite+가 Legend로 조정되지만 Legend 초과 영웅은 강등되지 않는다.
- 15층 이후에도 같은 RunState로 심층이 이어진다.
- 유물 낙인은 2/4/6/8에서 활성화되고 8개 초과 추가 단계가 없다.
- 실제 선택과 앱 추천이 다른 필드에 저장된다.
- 다음 화면 확인이 저신뢰 추론을 덮어쓴다.
- `(173 - 50) × 2 = 246` 상점 전이가 재현된다.
- `전체 평균 가격` 획득 후 상품 가격이 50으로 평가된다.
- 앱 재시작 후 최신 RunState가 복원된다.
- 비미궁 화면은 `OTHER` 또는 `UNKNOWN`이 된다.
- 낮은 confidence에서는 공격적인 추천이 나오지 않는다.
- 추천 결과에 영웅 이미지 또는 `이미지 미검증` 상태가 포함된다.
- AndroidManifest에 AccessibilityService나 게임 입력용 권한이 추가되지 않는다.

# 구현 순서

1. 현재 로컬 구현 상태를 조사한다.
2. 가장 이른 미완료 이슈를 확정한다.
3. 이름 보정 오류가 남아 있으면 먼저 수정하고 회귀 테스트를 추가한다.
4. #38 Golden 데이터와 metadata를 정리한다.
5. #38이 실제 승인 범위를 충족하면 #39 화면 판별로 진행한다.
6. #39 완료 후 #40 RunState를 연결한다.
7. #40 완료 후 #41 추천 엔진을 연결한다.
8. #39와 #40이 완료된 뒤 #42 배치 추천을 연결한다.
9. #41과 #42 완료 후에만 #43 출시 검증을 진행한다.
10. 근거 자료가 부족한 단계는 완료로 가장하지 않는다.

모든 이슈를 한 번에 흉내 내는 거대한 단일 클래스를 만들지 마라. 그렇다고 미래 확장을 위한 불필요한 인터페이스나 팩토리도 만들지 마라. 기존 코드 흐름에 가장 작은 변경으로 연결한다.

# 구현 완료 조건

- 기존 Android 앱 안에서 이계의 미궁 기능에 접근할 수 있다.
- 기존 화면 캡처와 Overlay 흐름을 재사용한다.
- 미궁 화면과 비미궁 화면을 구분한다.
- 승인된 관측만 RunState에 누적한다.
- 선택 추천에 상태 기반 이유가 표시된다.
- 영웅 추천에는 검증된 초상화가 표시된다.
- 추천과 실제 선택이 혼동되지 않는다.
- 앱 재시작 후 상태가 복원된다.
- 게임을 자동 조작하지 않는다.
- 기존 기능의 동작을 깨뜨리지 않는다.
- 필요한 최소 단위 테스트가 통과한다.
- Debug APK가 빌드된다.
